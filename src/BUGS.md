# Known problems in the code

Found on 2026-10-18 while writing the XML comments for every public member. A comment has to say what
the code does, so each place where the code does not match its interface (or its own name) was
written down. **None of these has been reproduced by running it unless the entry says so.** Each
one is a reading of the code by the person who wrote its comment.

How an entry is closed: a test that fails first, then the fix, then the entry moves to the
"Fixed" section with the commit. A problem is never closed by editing the interface comment to match
the code, unless the interface comment was the part that was wrong, and the entry says that.

Group letters: **R** real bug, **S** stub that reports success while doing nothing, **Q** needs the
real specification before anyone touches it, **I** the interface comment is probably the wrong part.

## Open

The first entries were written on 2026-10-18; later entries carry their own date. Where an entry in the S group says a method "throws", it used to report success and was changed to throw (see the Fixed section); it still does not do the job.

## Fixed

- 2026-11-23: chat through the XMSG node moved about 28 messages a second (16 chat programs, 4,800 lines, 171 s). Every call a program makes waits for the node's answer, and the node answered only on its next pump, after a fixed 20 ms sleep (about 31 ms on Windows); the chat server's 15 sends per line cost 15 ticks. `PluginServerHost.WaitForWorkAsync` now wakes the pump as soon as a program queues work. The same load: 1.4 s. Test `XmsgNodeServiceTests.Load_SixteenChatClients...`.
- 2026-11-23: the management API's Swagger page was never served. `AddRetroManagementApi` built the API description but nothing served it, while RetroServer's start-up banner printed `.../swagger`. `UseRetroManagementApi(enableSwagger)` now serves `/swagger` and `/swagger/v1/swagger.json` when it is on.
