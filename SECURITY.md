# Security policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Use GitHub's private reporting instead: go to the **Security** tab of this repository and choose
**Report a vulnerability**. That opens a private advisory visible only to the maintainers, and it
lets us work on a fix and publish it together with the disclosure.

What helps, in rough order of usefulness:

 - what an attacker gains - read a file they should not, crash the process, run code;
 - the shortest input that triggers it. A capture, a disk image or a byte sequence is worth far
   more than a description of one;
 - which component and which version or commit;
 - whether it needs a valid session, a local account, or nothing at all.

You will get an acknowledgement. This is a small project maintained in spare time, so please do not
read a slow reply as a lack of interest - if a week passes with no word, send a reminder through the
same advisory.

## What is in scope

RetroIO parses input that came from somewhere else: disk images, network frames and protocol messages. Those parsers are the part worth attacking. A reachable bug in any of them is in scope - a buffer read or write outside its bounds, an unbounded allocation driven by a length field, an infinite loop on a malformed frame, a path in an archive or a filesystem that escapes the volume it was opened from, or a decoder that trusts a count it was handed.

Also in scope: anything in this repository that handles a file or a stream it did not create - a
disk image, a configuration file, a capture, a saved session.

## What is not in scope

 - **The age of the protocols themselves.** X.25, XMSG, TNFS, Econet and the 1980s filesystems
   have no authentication, no encryption and no integrity checking worth the name. That is what
   they were; reproducing them faithfully is the purpose of this project, not a defect. Do not run
   any of it on a network you do not control, and do not expose a port of it to the internet.
 - A report generated by a scanner with no demonstration that the finding is reachable.
 - Denial of service by sending an unreasonable volume of traffic.
 - Anything requiring the attacker to already be able to run code as the user.

## Supported versions

There are no tagged releases yet, so the **default branch is what is supported**. Once releases
begin, the most recent one will be.

## Credit

Unless you ask otherwise, you will be named in the advisory and in the release notes for the fix.
